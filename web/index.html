A model writes the report. A program checks every claim.

The fact store is the ledger, read from the public mirror node at one consensus timestamp. The model marks each entity, number and judgement inline; the verifier resolves each one by lookup, with no model in the loop. What the ledger cannot support is shown as such.

The verdict on the ledger

    
What goes on the ledger is the verdict, not the text: the snapshot id, the counts, the hash of the report and the verifier version. Anyone can read it back with a consensus timestamp nobody can change.

    

    

  


  

    
What this does not do. It verifies that the text matches the ledger, not that the ledger is right. Numbers must be copied exactly; prose outside a claim is not checked, but every number outside one is counted. Thresholds here are demo policy; in a deployment they are the issuer's covenants.
